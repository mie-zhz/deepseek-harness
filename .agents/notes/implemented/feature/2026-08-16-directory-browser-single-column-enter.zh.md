# Agent Note: 单栏目录浏览器：点击进入，并用 `..` 回退

Status: implemented

[English](2026-08-16-directory-browser-single-column-enter.md) | 中文

## 问题

应用内「选择工作区目录」对话框采用 Miller 双栏预览：点击一行只是选中文件夹并在旁列出其子项，并不进入。习惯普通文件夹浏览的操作者预期点击即进入，且列表里没有 `..` 行可上一层。面包屑跳转和路径编辑可以上走，但列表本身只能往下。多出来的那一栏重复回答「我在哪儿」，却没有把回退做明显。

## 决策

browse 客户端的 `DirectoryBrowser` 是**当前层级的单栏列表**。点击一行即**进入**该文件夹（列出它）。离开文件系统根时，列表顶部有合成的 `..` 行，路径为该 listing 的父 crumb；点击即列出父目录。文件系统根不显示 `..`。**打开**采纳当前列出的层级。**新建文件夹**仍以当前列出的层级为目标，然后进入创建出的文件夹，以便打开采纳它。

安静导航、点击即编辑的路径栏、草稿跟随扫描、「显示隐藏」开关，以及嵌套创建对话框，仍按 [目录选择能力 seam](../architecture/2026-07-28-directory-picker-capability-seam.md) 的裁决。这些机制不再落地「父栏 + 子栏」双栏帧，也不再把选中行当作预览锚：一次列举调用替换整栏，前缀过滤作用于这一栏（有父目录时 `..` 始终置顶）。

本笔记持有列表交互。seam 笔记仍持有能力 kind、宿主列举策略，以及路径编辑器的取消／分隔符裁决；其中的 Miller 分栏事实由本笔记取代。

## 曾考虑的替代方案

- **保留 Miller 预览，只加 `..` 行。** 否决：预览栏正是抱怨点。在兄弟预览旁再放 `..`，仍要理解两栏，打开的目标（选中项 vs 当前列出）也仍然含糊。
- **用常驻路径框加「前往」替换面包屑，像某些文件管理器那样。** 再次否决，理由已记在 seam 笔记：面包屑已经在回答「我在哪儿」；本次只去掉预览栏并加上 `..`。
- **由宿主返回 `..` 条目。** 否决：宿主只列出真实子目录，且已经拒绝创建 `.`／`..`。上一层是客户端在宿主已盖章的 `crumbs` 上做的操作。

## 后果

- 点击文件夹列出其子项；点击 `..` 列出父目录，包括 Home 之上（展示根的 crumb 塌缩不挡住这一层回退）。
- 不再有「选中但未进入」的文件夹：打开与新建文件夹始终作用于当前列出的路径。
- 双栏落地、200ms 父层级等待、以选中项为锚的 crumb 跳转均已删除。测试与 workspace-management 的 aria golden 钉住单栏以及打头的 `..`。
